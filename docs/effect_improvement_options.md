# FedProxy-MA 效果提升方案与实验路线

更新日期：2026-11-16。依据当前代码、配置和本聊天中已有实验截图整理。本文没有修改训练实现，也没有运行新的模型实验；下列收益均为待验证假设，不预填准确率提升。

## 1. 建议先做什么

优先顺序为：**固定当前评测基线 → 融合强度校准 → 聚合权重与本地优化调节 → 相同预算下的重要性调度 → 有针对性的容量增加或蒸馏**。

三项无损通信优化可以继续保留。它们提供了更低的传输成本，但本身不提供新的训练信号。要提高效果，需要改善训练信号、跨任务优化、更新选择或从代理到完整 LLM 的迁移。

本文以“8 个任务客户端共同训练一个全局模型，最终融合模型评估八任务”为主。单任务 IID 实验应单独分析；任务平衡权重等方案在单任务场景中没有同样的依据。

## 2. 当前基线与历史数字的边界

当前解析后的配置为：

| 配置 | 代理块数（标准 32 层原模型） | 训练/上传块 | 每轮本地 epoch | 全局轮数 | 学习率 | 输入预算 |
|---|---:|---:|---:|---:|---:|---:|
| `configs/ma/base.yaml`、`lossless.yaml` | 16 | 12/10 | 5 | 10 | 5e-5 | 320 |
| `configs/ma/heterogeneous_ratio30.yaml` | 23 | 17/14 | 5 | 10 | 5e-5 | 320 |

两种代理都使用 rank 32、alpha 64、dropout 0.1、七类投影、每任务最多 3000 条训练数据。ratio30 的 remove_ratio=0.30 按 floor 规则实际删去 9 层，保留 23 层。

需要注意的已发生变化：

- 早期讨论的 MA base 为 10 个本地 epoch，当前文件为 5。实际服务器运行应以保存的 resolved/execution config 为准。
- 当前 MNLI 已统一训练和评测模板，具体见 `docs/mnli_evaluation.md`。旧截图不能直接与新模板得分混算为算法提升。
- 当前工作区没有 `runs/` 和最新服务器评测产物，因此不能判定最新瓶颈或承诺某方案必然提升。

历史截图中 MA 与 FedProxy 的 Fused ALL 分别约 67.874% 与 68.500%；SST-2、MNLI 下降约 2.294、2.638 个百分点，MRPC 上升约 1.961 个百分点。这支持优先检查跨任务折中，但不证明其原因，更不能把修正 MNLI 评测得到的提升归因于新的训练算法。

公平对照：同一代理规模、相同初始权重与层映射、训练/开发/最终评测划分、初始化种子和评测协议。23 层模型与 16 层模型属于不同资源档位；同质性独立模型与异质性单个全局模型也不直接混比。

## 3. 方案总览

“通信基本不增”指固定轮数、rank、层和坐标预算时数值规模基本相同；具体字节仍可能随零/常量编码改变。额外开发集评估与搜索时间另计。

| 优先级 | 方案 | 主要针对的问题 | 通信影响 | 训练/服务器成本 | 实现状态 |
|---|---|---|---|---|---|
| P0 | 数据结构与协议审计 | 信息截断、模板差异、比较口径 | 不增 | 审计及必要重评测 | structured 截断、审计、MNLI 统一已有 |
| P1 | 融合强度/开发集选 checkpoint | 代理更新回写完整模型后过强或不匹配 | 无新增联邦轮次 | 服务器多次开发集推理 | 需新增融合系数与开发集选择流程 |
| P1 | 减弱共识加权，任务权重对齐 | 任务独特方向被弱化，训练目标与宏平均不一致 | 基本不增 | 同量级训练 | beta 可调；任务权重指数/下限需实现 |
| P1 | 本地 LR、epoch、PCR、服务器步长 | 客户端漂移、正则过强、更新振荡 | 固定轮数基本不增 | 可持平或减少 | 常量超参数可调；调度器需实现 |
| P2 | 服务器动量/FedOpt | 多轮更新不稳定、各坐标尺度不同 | 基本不增 | 服务器额外状态和计算 | 需新增优化器、掩码与恢复逻辑 |
| P2 | 同预算的重要性层调度 | 轮转没有利用层的实际适应价值 | 小量统计/计划元数据 | 统计开销及同预算训练 | 需新增效用评分和约束调度 |
| P2 | 残差与最终轮上传策略 | 有价值更新陈旧或未进入最终模型 | 可增加，需单独计量 | 小到中 | mu/TTL 可调；结束策略需实现 |
| P2 | 增加训练层，保持上传预算 | 部分层训练限制适应能力 | 上行预算持平，下行 G 增加 | 更多梯度/优化器状态 | 现有层数配置可支持，需调度审计 |
| P3 | 任务相关代理选择/校准 | 通用 Alpaca 重要性与下游任务不匹配 | 同规模时基本持平 | 新校准和完整重训 | 更换校准源/目标需接入 |
| P3 | 公共数据蒸馏/融合后短程校准 | 剪层或融合改变表示，遗忘通用能力 | 可不增客户端模型载荷 | 增加服务器训练或教师成本 | 尚未实现 |
| 研究方向 | LoRA 有效权重空间聚合 | A/B 因子冲突不完全等价于函数冲突 | 可能增加，需控制秩 | 实现复杂 | 不能直接替换现有 MA-H-TIES |

## 4. 优先级最高的具体方案

### 4.1 先确认输入完整性与验证协议

读取截断审计里的 `cue_missing_rate`、`hypothesis_missing`、`choice_label_missing` 和逐任务截断率。当前是 prefix 截断；只有发现结构缺失时，优先尝试相同 320-token 预算下的 structured 截断。它尽量保留问题、选项、前提/假设与答案提示，代码已有。

如果 MNLI/QA 的关键字段经常被截掉，该方向比增加模型容量更值得优先验证。SST-2 输入通常较短，不能未经审计就把它的下降归咎于长度。截断率接近零时跳过此方向。

模型选择必须使用未参与训练、也不承担最终报告职责的开发集。优先利用既有合法开发集；没有时先冻结划分，并让基线与候选共同重建对照。不能在训练结束后将已参与优化的数据重新命名为泛化开发集。服务器侧融合校准需要其有权使用的开发数据；真实私有联邦数据不能默认集中到服务器。

所有方法使用同一最终评测协议。修改评测模板属于协议修正，应对基线和候选一起重评测，不单独计为模型能力提升。

### 4.2 融合强度校准：最快可验证

当前 `workflows.py::fuse` 先合并代理 LoRA，再通过 `fusion/plug_in.py::replace_mapped_layers` 将对应代理层写回原始模型，等价于固定使用完整强度的适配更新。

对映射层引入一个全局系数 gamma：

```
W_fused = W_original + gamma * Delta_W_adapter
```

其中原始层与冻结代理基座必须通过映射和权重来源对应。先用已保存 checkpoint 在独立开发集测试 gamma∈{0.5, 0.75, 1.0, 1.25}，gamma=1 为对照；先只用一个全局系数，避免逐层调参过拟合小开发集。

原因：LoRA 在删层后的代理上下文中学习，放回完整 32 层模型时，其他层改变了输入分布和残差路径。适配更新的最佳幅度未必恰好为 1。该方案可以在已有权重上验证，不需要重复联邦训练，但要增加服务器开发集推理、导出/加载成本。

正确缩放对象是 Delta_W=(alpha/r)BA，或只缩放一个因子/适配器整体系数；同时将 A/B 都乘 gamma 会把有效更新变成 gamma²。它也不等同于联邦训练时的 server_lr；后者会改变后续整个训练轨迹。

可进一步比较开发集选择的早期 checkpoint。所有方法获得同样的选择规则和搜索预算；主要结果仍可同时保留固定第 10 轮成绩。直接平均多个 checkpoint 的 A/B 不等于平均其有效权重，不能直接当作普通模型平均。

### 4.3 聚合权重与宏平均任务目标对齐

`ma/aggregation.py` 的当前客户端权重可写成：

```
w_i ∝ n_i * exp(beta * chi_i * consensus_i)
```

最终 ALL 却是八任务等权平均。在“一客户端一任务”的设置中，样本量不同会使训练权重与评价目标存在差异；同时，与其他任务方向不同的更新可能只是任务特有知识，不能自动解释为不可靠更新。

最小实验先只把现有 `ma.aggregation.beta` 从 1 改为 0.5 或 0，保持符号筛选、训练预算等不变。beta=0 仍按样本量加权，并不等于任务等权。

如果确有任务权重失衡，再实现：

```
q_i ∝ n_i^a * exp(beta * chi_i * consensus_i)
w_i = (1-epsilon)*q_i + epsilon/K
```

其中 a∈{0,0.5,1}，epsilon 可先取 0 或 0.1。a=0、beta=0 对应任务客户端等权；epsilon 为每个任务保留最低权重。不要同时扫描所有组合。

此方案不要求改变上行参数数量，适合优先研究。需要记录各任务客户端的权重、更新范数、更新被接受比例及开发集变化，确认是否真的改善了弱任务，而不是只将性能从 MRPC 转移到其他任务。

目前 `federated.fedavg_weighting` 不控制这条 MA 权重公式；只改该字段无法实现 MA 任务平衡，必须改 MA 聚合代码。

### 4.4 先调优化强度，再增加训练量

当前每客户端每轮都重建 AdamW，固定 LR=5e-5、本地 5 epoch，PCR lambda=1e-5，server_lr=1。优先根据日志选择以下单因素对照：

| 观察 | 第一项候选 | 判断依据 |
|---|---|---|
| 本地 loss 降但融合开发集变差 | local_epochs 5→2，或 LR 5e-5→2e-5 | 限制任务专化/客户端漂移 |
| 多轮分数和更新幅度振荡 | server_lr 1→0.5 | 减小每轮全局更新幅度 |
| task loss 几乎不降且 PCR 很强 | lambda 1e-5→3e-6/1e-6 | 放宽冲突方向上的约束 |
| 梯度偶发尖峰 | max_grad_norm=1.0 | 对比裁剪发生率、稳定性与最终效果 |
| 后期适配过强或过拟合 | 后期 LR 衰减 | 减少收敛末期扰动 |

这些都是候选，不是断言当前参数错误。PCR 的数值量级取决于大量坐标的加权平方和，不能只凭 lambda 小就断言其作用小。现有 task_loss/raw_pcr_loss/weighted_pcr_loss 能用于初筛；若仍难定位，可增加正则与任务梯度范数对比，但需计入统计开销。

**当前 `scheduler` 和 `warmup_steps` 虽然出现在 YAML 中，`federated/client.py` 尚未创建或步进学习率调度器。只修改字段不能得到 cosine/warmup。** 实现时明确采用全局轮次还是本地 step 调度；不应每轮重新长时间 warmup 而未意识到有效学习率预算改变。

减少本地 epoch 而固定 10 轮可能降低训练成本，但也可能欠拟合。若同时增加轮数保持训练步数，要重新计入累计通信。

## 5. 针对当前框架的方法改进

### 5.1 服务器动量或自适应优化

在 MA-H-TIES 产生更新后使用服务器动量，或参考 FedAdam/FedYogi。先从较简单的动量对照开始，再考虑二阶状态，避免一次叠加多个新机制。

该方向主要增加服务器 O(D) 状态；FP32 一阶、二阶两个状态在 16 层 rank32 下约 305 MiB，不必下发给客户端。客户端载荷预算可保持不变，但实际编码包长可能受状态取值变化影响。

必须显式处理“无人观测”和“符号未通过”的坐标：旧动量可能使 g=0 的坐标仍发生更新。若要保持当前拒绝语义，需额外的服务器更新掩码；同时明确动量衰减、二阶统计与 bias correction 的计时规则，并写入 checkpoint。不能只把零填进 Adam 就宣称保留原缺失语义。

FedOpt 文献为可行性提供依据，但其收敛结论不能直接覆盖 MA 的掩码、稀疏残差和符号过滤组合。

### 5.2 相同预算下的重要性调度

当前 `ma/scheduler.py` 按固定种子轮转，主要保证覆盖与上传机会，没有利用不同层对任务适应的价值。

建议保留每客户端 12 个训练块、10 个上传块、1 个共享锚点及总坐标预算，用最近若干轮的层更新/梯度统计估计效用，分配一部分名额给高效用层，保留强制探索和轮转名额。

约束包括：upload⊆train、锚点共享、每块足够重叠、残差在 TTL 内有上传机会。未训练层的效用是未知或陈旧，不能当作零，否则调度会永远排斥它们。更新范数应按参数量与尺度归一化，避免仅偏向大张量。

每客户端每轮额外报告 16/23 个层级标量的裸数值只有几十到百余字节，实际还需消息元数据；可使用现有统计，不上传完整梯度。该方案比直接扩大所有客户端 rank 更容易保留成本优势，也有较清晰的方法研究价值。指标的预测能力需通过单独消融证明。

### 5.3 残差、陈旧度与训练末尾的信息损失

当前残差 TTL=4、mu=0.1，会丢弃过期残差，且最后一轮仍可能有训练但未上传的信息。先统计 `residual_expired_l1`、`residual_retained_l1`、层级等待和最终未发送状态。

如果过期残差显著，可比较 mu=0.1 与 0.03/0；如果过期不显著，延长 TTL 很可能没有收益，反而增加陈旧信息和存储。

更有效的方向可能是最后几轮提高上传覆盖或偏向清理累计残差。强制末轮清空残差需要新协议和额外通信，可能把陈旧或冲突更新重新带入最终模型；不能保证提高效果，也不能继续沿用原通信预算。

公共探针配置 `probe.yaml` 已可用，但 base 的非锚点保留率为 80%，交集通常比强稀疏方案充足。只有诊断表明有效共同观测不足时，再尝试从固定 Top-k 名额中保留 5% 探针；否则它可能占用更重要的更新坐标。

### 5.4 用少量成本恢复适应能力

较稳妥的容量对照是训练层 12→14，同时保持上传 10 层、保留率 0.8、rank32。这样上行数值/索引预算不增加，可训练参数量约增加 16.7%；未做零省略时，下行主体从 7D 变为 7.5D，约增加 7.14%。端到端训练时间不会简单按这个参数比例增长，需实测。

新增训练层的知识仍要靠之后的上传机会传递，需先通过调度和 TTL 审计。不能保证增加的训练全部有用。

若采用 23 层代理，应另在该规模内做 17→19 训练块的对照，并单独计算成本。16→23 层会增加代理规模、计算及 LoRA 载荷；不能把容量提升包装成相同资源下的算法改进。

直接 rank32→64 会近似翻倍适配器相关载荷和状态，优先级低于上述选择。

### 5.5 任务相关代理与蒸馏

当前块影响在公共 Alpaca 校准集上估计。可以在相同保留层数下，尝试经授权、与八任务分布更接近且不含最终评测样本的校准数据，或者在块选择中加入结构覆盖约束。

更换保留层会改变整个学习问题，需重新生成代理、映射、初始化与完整训练；所有对照应共享同一新代理。若同时改善 FedProxy 和 MA，它属于框架层面的改进，不能全部归因于 MA 聚合。

蒸馏可考虑：公共输入上的原始 LLM 软目标用于代理预校准，或在最终融合 LLM 上执行短程公共数据校准。原始教师能约束通用能力，但不保证比当前模型更擅长目标任务；应使用开发集确认 CE/KL 权衡。

保留客户端不接收完整原始 LLM 的边界：教师可在服务器离线生成允许共享的监督，或训练仅发生在服务器。公共数据、教师输出、教师推理和服务器优化成本都要计入，不能称作免费收益。

FedDF 的多客户端模型集成蒸馏可供参考，但本项目服务器只收到部分、稀疏且可能含旧残差的更新，不能无成本重建全部客户端本地模型。若采用它，需额外设计教师信息来源和通信预算。

### 5.6 LoRA 有效权重空间：更长期的研究方向

一般情况下，分别平均 A/B 因子与平均有效权重不同：

```
(sum_i w_i B_i)(sum_i w_i A_i) != sum_i w_i B_i A_i。
```

MA 当前还在因子坐标上做 PCR、Top-k 和符号筛选。因此因子方向不完全等同于模型函数方向，可能存在需要研究的聚合失配。但这不是已经证实的当前误差来源，也不表示现有设计逻辑上无效。

可参考 FLoRA 的堆叠式聚合，或研究有效 Delta_W 空间的相似度/低秩重构。实际采用时必须处理：堆叠秩增长、固定 rank 下的近似误差、部分观测缺失、历史残差和统一因子坐标。重新分解 A/B 会影响下一轮 PCR 与残差的坐标含义，不能每轮随意 SVD 后接回原算法。

建议先做完整观测的小规模诊断，再考虑与 MA 的组合。该方向研究价值较高，但不适合作为最快提升现有结果的第一步。

## 6. 实验执行顺序

所有候选先固定无损通信开关，使用独立命名配置/目录；不修改作为对照的 base。建议逐项执行，避免全组合搜索：

| 阶段 | 对照内容 | 是否需要新联邦训练 |
|---|---|---|
| E0 | 当前预算下 FedProxy 与 MA 的同协议基线，确认最新薄弱任务 | 缺少匹配基线时需要 |
| E1 | 现有 MA checkpoint 的 gamma 校准与开发集轮次选择 | 否；需要独立开发集推理 |
| E2 | beta=1 对比 0.5/0；若证据支持，再引入任务权重 | 是 |
| E3 | 根据日志只选一个方向：LR 降低、server_lr 降低或 PCR 减弱 | 是 |
| E4 | 固定预算的重要性调度，或 12→14 训练层容量对照 | 是 |
| E5 | 将已单独有效的两个方案组合，再检查相互作用 | 是 |

若结构审计发现明显截断，先执行 structured 对照，并据此建立后续共同基线。若运行已经是 ratio30，在同一档位完成上述比较，不沿用 ratio50 数字。

单种子短程实验可排除明显失败候选，但不应仅因前两轮分数较低就淘汰可能晚收敛的方案。最终候选使用至少 3 个匹配种子，条件允许时用 5 个，并保留相同搜索预算的 FedProxy/MA 基线。

主要目标为最终融合 LLM 的 ALL 提升，配对差的置信区间应支持正向提升；同时报告 QA、GLUE、逐任务变化与最差任务下降。可预先设定工程目标，例如 ALL 提高至少 0.5 个百分点且无单任务明显退化，但这只是验收目标，不是预测收益。

同时报告固定轮数成本和达到同一效果的累计成本：客户端 GPU 时间/显存、服务器训练与评测时间、上下行实际包长、初始化与新增教师数据通信。若增加轮数或教师训练，必须纳入成本。

## 7. 不建议优先采取的方式

- 仅增加 epoch/轮数：可能放大任务漂移，且增加成本；应由训练/开发曲线支持。
- 一开始叠加 QLoRA、DoRA、秩扩展、聚合变更：难以归因，且资源口径同时改变。
- 为每个任务单独保留/路由适配器后与单全局模型比较：改变部署目标、存储和推理协议，需单列个性化实验。
- 直接替换为 SCAFFOLD：控制变量有降低漂移的研究依据，但标准实现增加状态及控制变量通信；与部分观测、符号聚合的结合需要新设计。
- 按最终评测结果选融合系数或任务权重：会污染最终比较，应使用独立开发集。
